## Règles propres à ce repo

## Project purpose

`f1-strategy-analyst` is block 3 of a portfolio "internal AI platform", and its first client app: an agent that writes sourced Formula 1 race strategy debriefs from timing data and FIA regulations, and stops for a human analyst before publishing. Every model call goes through `llmops-gateway` with the `f1` team's key. The user cares about F1 beyond the portfolio: the front end is meant to become a polished product.

Planning lives in Linear (team key `LAB`, project "Plateforme IA · Analyste stratégie F1", milestones 4.1 to 6).

## Design principles (decided 2026-10-10, see the Linear issues)

- Numbers never come from the LLM: deterministic, unit-tested tools compute them (LAB-144), and the agent's `verify` node checks every number and source of a draft.
- Production retrieval (LAB-186): query rewriting (French questions, English FIA corpus), hybrid dense + sparse search with RRF, reranking through the gateway's `rerank` alias, an abstention threshold, citation checks. Each stage can be switched off to measure its gain (ablation). LAB-147 is a deliberately naive baseline.
- The agent is a fixed LangGraph graph, not a free ReAct agent: the LLM only fills bounded nodes with validated structured output, and code does the routing. Three human stops: clarification, plan validation, point-by-point review with a reason for every rejection.
- The app speaks French; the corpus stays in English.

## Layout and rules

- `src/core/`: the reusable foundation; `src/f1/`: the theme. `core` never imports `f1` and holds no F1 vocabulary (ADR-011); `tests/unit/test_architecture.py` enforces the import rule.
- The gateway runs with `drop_params: false` since LAB-199: a parameter an alias's model does not take is refused with a 400 `UnsupportedParamsError` instead of being dropped silently.
- `core.gateway.gateway_client()` is the only way to reach a model, reranking included. Settings come from `GATEWAY_URL` and `GATEWAY_API_KEY` (the team's virtual key, never the master key). Its transport (`GatewayTransport`) waits out the key's rate limit (60 requests and 100,000 tokens a minute) on a 429, until LiteLLM's `reset_at`, and names the app as `user` for the gateway's cost per end user (`f1-rag` for the RAG). The OpenAI SDK 3 runs on `httpx2`: its transports and test mocks are `httpx2` ones.
- Race data (LAB-143): every session of a weekend (`FP1`-`FP3`, `SQ`, `Q`, `S`, `R`, since schema 3); always filter on `session`. `src/f1/data/` ingests FastF1, OpenF1 and Jolpica-F1 into Parquet files on S3 (`core.lake.Lake`, SeaweedFS locally), queried with DuckDB through `f1.data.connect()`. Tools read the lake, never the APIs. Schema in `src/f1/data/schema.py`, documented in `docs/data-schema.md`: bump `SCHEMA_VERSION` on a breaking change. A round is written then marked by `_manifest/<season>/<round>.json`; reruns skip marked rounds.
- Tools (LAB-144): `src/f1/tools/`, one module per tool, each a `core.tools.Tool` (Pydantic input and output, JSON schema for tool calling), bound to the lake by `f1.tools.catalog(RaceData(connect()))`. A request the data cannot answer raises `core.tools.ToolError`, never a guessed number. Assumptions and limits in `docs/tools.md`; reference races in `tests/integration/test_tools_reference.py`.
- FIA corpus (LAB-145): `src/f1/corpus/` downloads the sporting regulations (last issue per season) and the stewards' decisions from fia.com (10 s between requests, as its robots.txt asks; cache in `.cache/fia/`, never committed), parses them by structure (article or section -> paragraphs; decision -> summary and reasons) and syncs them into Qdrant through `core.retrieval.index.HybridIndex` (`fia_chunks` with `dense` and `bm25` vectors, `fia_parents`). Only chunks whose content hash changed are embedded. Details and limits in `docs/corpus.md`.
- Retrieval pipeline (LAB-186): `core.retrieval.pipeline.RetrievalPipeline`, six traced steps (understand, search, rerank, gate, generate, verify), switches and models in `PipelineConfig` (`RAG_*` env). The theme gives a `Profile` (`f1.rag.profile.FiaProfile`): filters and references are read by code, never by the model; reranking reads the English rewrite, so the rewrite prompt must keep the question's subject. Rewriting runs on `chat-medium`, answers and checks on `chat-pro` (gateway LAB-185); `chat-small`/`chat-large` cannot follow the JSON schemas. `just ask`, `just rag-eval` (ablation and threshold calibration on `evals/datasets/dev.jsonl`, never the test set; `--runs N` averages the threshold). Details in `docs/rag.md`, choices in ADR-024. Tracing: `core.tracing` (Langfuse, f1 project keys `LANGFUSE_*`, off without keys).
- Session summary jobs (LAB-196): `core.jobs.run_batch` publishes jobs to llmops-platform's RabbitMQ (exchange `jobs`, key `inference`, format in llmops-gateway/worker/README.md) and collects replies on a durable queue, or finds failed jobs in `jobs.inference.dead`. `f1.jobs.facts` computes each session's facts from the lake, drivers in full names (a model expands codes wrongly); `f1.jobs` checks every number and name of a summary against them. `just season-jobs 2025 [--simulate]`. Details in `docs/jobs.md`.
- Baseline (LAB-147): `core.baseline.Baseline`, the naive reference: dense search only, up to 3 tools chosen in JSON validated by code (not native tool calling, which `chat-pro` silently dropped until LAB-199; the agent's nodes work the same way), an answer whose cited ids and numbers are checked (`core.numbers`), withheld after one failed retry. F1 side in `f1.baseline` (prompt in `prompt.txt`, `user: f1-baseline`). Tools gained `find_race` and `session_result`. `just baseline "<question>"`. Details in `docs/baseline.md`.
- Evaluation dataset (LAB-146): `core.evals.dataset.Case`, one format for every family (data, computation, strategy, regulation, retrieval, out_of_corpus, safety), each with its `origin`; exports to promptfoo, Ragas and Langfuse Datasets. `f1.evals.generate` computes the data, computation and strategy cases from the lake and tools (seed 146, reproducible byte for byte); the strategy rule (`f1.evals.strategy`, LAB-201) pairs stops of the same rank, reads penalties served, names neutralizations, writes the facts of the cycle, and asks some questions on a false premise; `evals/datasets/handwritten/` holds the written and model-drafted ones. Split by a hash of the id: tune on `dev.jsonl` only. `just eval-dataset` (`check`, `push`, `draft-regulation`, `review-candidates`). Details in `evals/README.md`.
- Evaluation harness (LAB-148): `core.evals.harness` runs a system once per case and appends each record as it comes (`--resume` goes on with an interrupted run), then scores the records: promptfoo (`npx promptfoo@0.123.1`, recorded-answers provider, checks in `evals/promptfoo/assertions.js`) for data/computation/safety/out_of_corpus, Ragas in its own environment (`evals/ragas/`, openai < 3) for regulation, `core.evals.judge` for strategy, Recall@5/MRR/nDCG@5 for retrieval. `just eval` (`--sample`, `--family`, `--model`, `--push`, `--check`, `judge-sheet`, `agreement`, `thresholds`, and `models`, the side-by-side comparison of LAB-150). Tools choices in ADR-012. The agent as the app answers (LAB-154): `just eval --system agent` (`f1.evals.agent.AgentSystem`: the router, then the retrieval pipeline or `Chat`; no path or a debrief asked: data when the question names a race, a driver or a team), `just eval systems --runs <baseline> <agent>` side by side, `just eval failures --runs <run>` by cause, `just eval acceptance` the share of reviewed points accepted as written (`wrong_meaning` is a rejection reason since). Details in `docs/evaluation.md`.
- Debrief agent (LAB-151): `core.agent` is a fixed LangGraph graph (no F1 vocabulary) whose nodes a `Theme` fills: parse, resolve, clarify ⏸, plan (a closed catalog built by code; the model only picks ids), approve_plan ⏸, run_tools, detect_events, retrieve_rules (`RetrievalPipeline.answer_within`), draft, verify (code: every number in a cited analysis or rule source, `Theme.check` for numbers in words; three drafts at most, then "unverified"), review ⏸, apply, publish. Interrupt nodes only ask and record; answers outside what was asked are asked again. Limits per request (`AGENT_*`), counted by `core.gateway.usage_scope`; one Langfuse span per node in one trace across resumes (`Tracer.trace(trace_id=...)`, flushed after each invoke). State saved by the PostgreSQL checkpointer (`core.agent.store`, serializer allowing the state's models), published debriefs in the `published` table. `f1.agent.theme.F1Theme`: season and Grand Prix read by code, names matched to the entry list, the `penalties` tool (not in the baseline's catalog, so its prompt is unchanged), every node on `chat-pro`, `user: f1-agent`. `just debrief`. Details in `docs/agent.md`, choices in ADR-025.
- `compose.yaml` runs Qdrant, PostgreSQL (port 5435, since LabbTech Auth's database holds 5433), the S3 store (SeaweedFS on port 8334, since llmops-gateway's Langfuse holds 8333), and the API (8000) and the front (3000) built from their Dockerfiles. The gateway runs from `../llmops-gateway` (`just gateway-up` there); the CLIs run on the host with `uv run`, and `just api` / `just web-dev` reload on ports 8001 / 3001.
- Front (LAB-187): Next.js 16 in `web/`, pnpm (pinned by `packageManager`, through corepack), Biome, Vitest, Playwright, Tailwind 4 and shadcn/ui (copied in `web/src/components/ui/`). Pages are server components calling the API on `API_URL` through openapi-fetch, typed by `web/src/lib/api/schema.d.ts`, generated from `web/openapi.json` (`just web-gen-client`). After any change to `src/f1/api.py`'s routes or models, run `just web-gen-client` and commit both files: `tests/unit/test_api.py` fails otherwise. Texts in `web/src/messages/fr.ts` (never inline), colours as tokens in `globals.css` only (dark only; `tokens.test.ts` checks AA contrast and that no component holds a colour; red text is `text-primary-text`), design system in `docs/design.md` and on the internal page `/design` (LAB-188). Details in `docs/web.md`, choices in ADR-026. Race pages (LAB-202): `f1.grand_prix.GrandPrix` reads the calendar and a race's page from the lake with the tools' functions, never a model (`/seasons`, `/races`, `/races/featured`, `/races/{season}/{round}`; `/debriefs?season=&round=`); front routes `/grand-prix` and `/grand-prix/<season>/<round>`, components in `web/src/components/race/`. HITL screens (LAB-152): `/en-attente`, `/debriefs/<id>` (one view per stop, answered by server actions), `/debriefs`, `/journal`; review decisions logged by `RequestStore.log_decisions` (`decisions` table, `GET /decisions`), exported as candidate cases by `just eval-dataset review-candidates`; `E2E_AGENT=1 just web-test` runs the full path with the real agent. Targeted question (LAB-203): `Agent.start(..., given=...)` lays chosen subject fields over the parsed ones (never asked); F1's `question` mode adds the agent-only `race_strategies` and `race_weather` tools and an answer-first draft; `POST /debriefs` takes `season`, `round`, `question`; the GP page's `QuestionForm` with suggestions read from the race (`web/src/lib/suggestions.ts`). Questions on a published debrief (LAB-205): `core.agent.chat.Chat` (scope by code, closed catalog, `check_point`, one more reply then withheld, `AGENT_CHAT_*` limits), `f1.agent.debrief_chat()` (`user: f1-agent-chat`), `questions` table, `GET`/`POST /debriefs/{id}/questions`, thread under the debrief; `F1Theme.check` refuses an article named without its source. Free question of the home page (LAB-206): `f1.router.Router` routes by code (debrief, rules, data, or the analyst chooses), with the drivers and teams of the lake (`GrandPrix.people`); `f1.questions.FreeQuestions` answers on the path (retrieval pipeline, or `Chat` on a subject from `F1Theme.free_subject`), `free_questions` table, `POST`/`GET /questions`; `just eval routing --check` measures it on the dataset (95 % target). Race charts (LAB-189): `GrandPrix.laps` / `GET /races/{season}/{round}/laps` (position, gap to the leader at the line, lap time, tyres, lap by lap; each stint's pace from `degradation.fit`; the events linked to their FIA text by `f1.race_rules.RaceRules`, read in Qdrant by code), drawn in SVG without a chart library (`web/src/lib/race-chart.ts`, `race-charts.tsx`, ADR-026), the GP page's « Course » tab (`?onglet=course&pilotes=`); a debrief point opens the chart of the analyses it cites (`Fact.chart` from `f1.charts.chart_for`, zoomed on their laps). Strategy simulation (LAB-213, LAB-214): `f1.tools.simulation` (by difference with the strategy raced: stints' fuel-corrected lines from `degradation.fit`, bent past their last tyre age by half their convex curvature (LAB-216, `degradation.wear`), another compound by `degradation.compound_shift` measured on the other drivers, stops' measured cost; French refusals), validated by `just simulation-validate 2025` (`evals/reports/simulation-2025.json`, its error shown with each projection), `GET /races/{season}/{round}/simulation`, the GP page's « Simulateur » tab. Duel of drivers (LAB-212): `f1.duels` (`GET /duels?season=&drivers=A&drivers=B`, `GET /seasons/{season}/drivers`), two queries a season, gaps first less second, definitions in `docs/tools.md`; page `/duel` (`web/src/components/duel/`), opened from the « Course » tab when two drivers are highlighted. Season view (LAB-215): `f1.season` (championship from the results with the regulations' count-back, form, teams' qualifying and race pace in %), `GrandPrix.season` kept until another round, `GET /seasons/{season}/overview`, page `/saison` (`web/src/components/season/`). Accounts (LAB-192): LabbTech Auth (labbtech-universe, Google sign-in), its shared `auth_token` cookie; `core.auth.Authenticator` checks it against the SSO's JWKS (`AUTH_*`), analysts by account id in `AUTH_ANALYSTS`; analyst-only routes (`dependencies=Analyst`), unpublished requests hidden from readers; without `AUTH_JWKS_URI` the API is open (locally, CI). Front: `apiClient()` forwards the token, `fetchSession()` (`GET /me`), `AnalystOnly` / `ReservedPage`, renewal in `src/proxy.ts`, `/connexion` and `/deconnexion`; details in `docs/web.md`. Debriefs that explain (LAB-207): each tool output gets a French `lecture` written by code (`f1.agent.readings`); a debrief is a summary, titled moments and a takeaway (`Point.kind`, `Point.title`), the moments in race order by the first lap they name (`Point.when`, shown on a timeline); after the numbers, `Theme.faithful` checks the meaning (who was ahead by code with `order_problems`, the rest by a model claim by claim), in the graph and in `Chat`. Prepared debriefs (LAB-204): `f1.prepare` (`just debriefs-prepare 2025 --round 16`, `--categories team,moments,driver`, `--budget` in tokens) runs the agent in this process up to each review, the plan approved by code; thread ids derived from race and target, so a rerun skips what is prepared; `subject["prepared"]` groups them on the race's page (`PreparedDebriefs`). The top 5: `f1.tools.moments.key_moments` (the theme's tool, not the baseline's) finds and ranks moments by the championship points they moved; `subject["moments"]` plans them by code and drafts one point each. Next.js 16 differs from older versions: read the docs of the installed version in `web/node_modules/next/dist/docs/` before writing front code.

## Commands

Tasks run with [just](https://just.systems/) (`justfile`, which loads `.env`); there is no Makefile. Run `just` to list recipes.

- `just up`: build and start Qdrant, PostgreSQL, the S3 store, the API and the front, wait until healthy, then run `just smoke`. Creates `.env` from `.env.example` if missing.
- `just smoke`: `tests/integration/`, against the stack and the running gateway (chat, embeddings, model list of the `f1` key, Qdrant, S3), plus the real data sources: the 2025 Italian GP checked against official results and Jolpica-F1 (needs the network).
- `just corpus 2025` (or `2024 2025 2026`, `--regulations-only`, `--decisions-only`, `--refresh`): FIA corpus into Qdrant; needs the gateway for embeddings.
- `just eval`: the baseline on the test set, a score table per family (about 30 minutes at 60 requests a minute; `--sample 8` for a quick look). `just eval routing --split dev --check`: the home page's router on each family, without a call.
- `just eval-dataset`: rebuild `evals/datasets/dev.jsonl` and `test.jsonl` from the lake and `handwritten/` (a minute); `check` compares, `push` sends them to Langfuse.
- `just season-jobs 2025` (`--round 16`, `--simulate`): one summary job per session through the job queue; needs llmops-gateway's stack.
- `just ask "<question>"`: a question on the FIA rules, answered with sources; `just rag-eval`: retrieval ablation and threshold calibration (about 20 minutes).
- `just ingest 2025` (or `2024 2025 2026`, `--round 16`, `--force`): race data into the lake; `just sql "<query>"` queries it.
- `just test-unit`: unit tests, no stack, under a second. `just test` runs everything, with pytest arguments passed through.
- `just api`: the FastAPI app with auto-reload (port 8001).
- `just web-install` once, then `just web-dev` (port 3001), `just web-test` (`unit` to skip Playwright), `just web-gen-client`.
- `just image`: build the API's and the front's Docker images as the CI does.
- `just lint`: every pre-commit hook (whitespace, YAML, Markdown, gitleaks, ruff, mypy strict on `src` and `tests`).
- `just down`: stop the services; `just down --volumes` also deletes the Qdrant index, the database and the lake.

## CI and releases

`.github/workflows/ci.yml` runs pre-commit, a full-history gitleaks scan, the unit tests and the PR title check (PRs are squash-merged). The integration tests do not run in CI yet. `.github/workflows/eval.yml` is the evaluation gate (LAB-149): on a non-draft PR touching `src/`, the dataset or the scorers (open PRs as drafts while iterating: each evaluated push costs about $0.10), the agent (`--system agent`, LAB-210) on 10 test cases per family against llmops-gateway started from a pinned release (`GATEWAY_VERSION`, `.github/actions/gateway`, GHCR images), compared with the agent's reference runs on main on the same cases (`core.evals.compare`; thresholds and reference runs per system in `evals/thresholds/<system>.json`, the baseline on demand with the `system` input), with a PR comment and the run's cost; a full run weekly. It needs the `SCW_SECRET_KEY` and `EVAL_DATA_KEY` secrets. F1's live timing refuses GitHub's runners, so the lake is never built in CI: `just eval-data-publish` uploads the local lake and Qdrant snapshots (`just index-save`), encrypted, to the `eval-data` release and names the asset in `evals/eval-data.json`; the CI runs `just eval-data-fetch` and `just index-load`. `.github/workflows/web.yml` runs on changes to `web/` only: Biome, types, Vitest, the generated client compared with `web/openapi.json`, and Playwright against the API of the commit. `.github/workflows/images.yml` runs release-please and builds the API's and the front's images with llmops-platform's shared workflow (Trivy, then on main: GHCR, SBOM, cosign), pinned to a commit of its main branch. `CHANGELOG.md` is written by release-please: never edit it by hand.
